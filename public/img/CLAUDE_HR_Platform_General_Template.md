# دليل عام لمنصة موارد بشرية

هذا الملف قالب إرشادي عام للمشروع. لا يضم بيانات فعلية أو أسماء أو أرقامًا خاصة.

---

## هوية المشروع

- **النوع:** منصة لإدارة عمليات الموارد البشرية.
- **البنية:** تطبيق ويب أحادي المصدر يمكن تشغيله داخل المتصفح.
- **التقنية:** HTML وCSS وJavaScript دون افتراض إطار عمل محدد.
- **التشغيل:** يحدد حسب بيئة المشروع، مع الفصل الواضح بين البيانات التجريبية والبيانات الحقيقية.
- **واجهة الاستخدام:** عربية من اليمين إلى اليسار، مع الالتزام بدليل الهوية المعتمد عند توفره.
- **التسليم:** كل إصدار موثق برقم نسخة وتقرير موجز بالتغييرات والفحوصات.

## مبادئ لا تُكسر

1. أي تغيير مالي يجب أن يكون صريحًا وقابلًا للتدقيق، مع توضيح أثره قبل اعتماده.
2. لا تُحذف سجلات الحضور أو أي بيانات مصدرية؛ تُؤرشف وفق سياسة معتمدة عند الحاجة.
3. لا تُحتسب ساعات العمل عند نقص السجلات اللازمة، إلا باعتماد يدوي موثق.
4. يعتمد النظام على معرّف وظيفي فريد، لا على الاسم وحده.
5. يجب دعم الورديات التي تعبر منتصف الليل.
6. قواعد العمل والمعادلات والإشعارات تُدار من الإعدادات، لا من قيم ثابتة داخل الكود.
7. الفترات المغلقة تحفظ كلقطات معتمدة ولا يعاد تعديلها دون إجراء رسمي.
8. صلاحيات الاعتماد المالي محددة بدور معتمد ومفصولة عن صلاحيات الإعداد أو المراجعة.
9. لا يتم النشر الخارجي أو تفعيل التكاملات إلا بعد اعتماد صريح وفحص مناسب.
10. لا تُعرض أي نتيجة أو إشعار على أنه مكتمل ما لم يتم تنفيذه والتحقق منه فعليًا.

## قواعد العمل والتواصل

- تُنفذ الطلبات الواضحة مباشرة، وتُطلب القرارات فقط عندما تؤثر على قاعدة عمل أو نتيجة مالية أو صلاحية.
- تُراجع اللغة العربية والإملاء في الواجهات والتقارير قبل التسليم.
- يحدد النظام سياسة موحدة للتقريب وعدد المنازل العشرية.
- لا يكفي فحص الكود؛ يجب اختبار النتيجة داخل الواجهة عند توفر بيئة اختبار.
- تُعالج الملفات المرفوعة عبر معاينة وتحقيق قبل اعتماد أي تحديث للبيانات.
- تُكتب التقارير بلغة واضحة، وتعرض الأثر قبل/بعد عند وجود تغيير، وتنتهي بالقرارات المطلوبة.
- لا تُتخذ قرارات غير قابلة للعكس، مثل الحذف أو الدمج أو الإغلاق النهائي، دون اعتماد صاحب الصلاحية.

## آلية العمل لكل إصدار

1. إنشاء نسخة عمل من آخر إصدار معتمد.
2. تنفيذ التعديل بطريقة قابلة للمراجعة، مع التحقق من أن التغيير يستهدف الموضع الصحيح فقط.
3. اختبار الدخول والصلاحيات باستخدام حسابات اختبار آمنة أو بيانات اعتماد مُدارة خارج الملف.
4. إجراء فحص شامل للواجهات والأخطاء والمعرّفات المكررة، ثم فحص مركز للشاشات المتأثرة.
5. عند وجود أثر مالي، مقارنة النتيجة قبل وبعد وتوثيق الفروقات بوضوح.
6. تسليم النسخة الجديدة مع تقرير يوضح التغييرات والفحوصات والقيود والقرارات المعلّقة.

## خريطة المكونات الأساسية

- **المحرك المالي:** مصدر موحد للأرقام المالية يمنع اختلاف الإجماليات بين الشاشات.
- **إدارة الفترات:** فتح الفترات وإغلاقها وحفظ لقطات معتمدة قابلة للمراجعة.
- **الأهداف والحوافز:** قواعد قابلة للتهيئة، واعتماد منفصل للأهداف أو الاستثناءات.
- **الصلاحيات:** فصل واضح بين العرض والتحضير والمراجعة والاعتماد.
- **الدوران الوظيفي:** تعريف موحد لمصادر بيانات المغادرة، مع استيراد ومعاينة قبل التطبيق.
- **إدارة المهام:** مساحات عمل ومراحل وتصنيفات وإغلاق دوري وتقارير ثابتة.
- **العمليات والإنتاج:** ربط ساعات العمل بالبيانات التشغيلية وفق فترة واضحة وأساس ساعات محدد.
- **الحضور والانصراف:** حفظ البيانات المصدرية، وإدارة الاستثناءات والاعتمادات بطريقة موثقة.
- **تجربة المستخدم:** واجهة متسقة تراعي سهولة الوصول وتقليل الحركة عند الحاجة.

## أخطاء يجب تجنبها

- وضع دوال أو متغيرات في نطاق لا تستطيع بقية مكونات النظام الوصول إليه.
- تغيير معرّفات بيانات داخلية عند تصحيح اسم معروض للمستخدم.
- تحميل البيانات أو ترتيب قواعد المعالجة بطريقة تسمح لخطوة لاحقة بإلغاء نتيجة خطوة سابقة.
- افتراض أن قيمة معينة محفوظة دون اختبار مصدرها وطريقة تخزينها.
- الخلط بين صلاحية الاطلاع وصلاحية الاعتماد.
- إجراء الاختبارات دون إعادة الحالة المؤقتة إلى وضعها الأصلي بعد الانتهاء.

## قرارات تنتظر اعتمادًا

- أي تغيير يؤثر على الرواتب أو الحوافز أو إغلاق الفترات.
- دمج السجلات المكررة أو حذفها أو إعادة بناء بيانات تاريخية.
- تعديل هيكل الصلاحيات أو مسؤوليات الاعتماد.
- تفعيل التكاملات الخارجية أو الإشعارات أو النشر العام.
- اعتماد معادلات جديدة أو استثناءات تشغيلية أو مؤشرات أداء جديدة.
